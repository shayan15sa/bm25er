** Use a buffered reader instead of loading the whole file into ram
When I tried to scan one of my repos, a header file imported by raylib was too large. readFileAlloc() is a nice convenient function, and I agree with your decision to limit the amount of memory this consumes, but since you don’t know the size of the files in advance and need to read many files, a better way is to set aside a sufficiently large buffer (ex: 4096) and do buffered reads without allocation.
example using the reader interface: [[https://cookbook.ziglang.cc/01-01-read-file-line-by-line/]]
** Skip binary files
1. On binary files: I’ve heard of a technique for detecting if you’re reading a binary file where you check the first 128 or so bytes to see if they’re all valid, printable characters. As far as I know there isn’t support in the standard for non-ASCII but just checking std.ascii.isAscii() would be okay.
2. I believe the way grep does it is by scanning the first buffer-load (e.g 32kB) it reads for null characters, or invalid UTF-8 encoding (e.g. overlong characters). I think you could use the functions in std.unicode to do that. I might give that a try actually - I have a crude zig version of grep which I made as an example in a library.
#+begin_src zig
/// First ensures the buffer is full (or EOF), then returns true
/// if the buffer consists entirely of UTF-8 codepoints.
///
/// Useful for distinguishing text files from binary files.
fn checkFileIsValidUtf8(reader: *std.Io.Reader) Io.Reader.Error!bool {
    const peek = reader.peek(reader.buffer.len) catch |err|
        switch (err) {
            Io.Reader.Error.EndOfStream => try reader.peekGreedy(0),
            else => return err,
        };
    // std.log.debug("Checking utf-8 validity for first {} bytes", .{peek.len});
    return std.unicode.utf8ValidateSlice(peek);
}

** DONE Memory Waste in addWordsForAFile
[[file:src/main.zig::111][Line 111 of main.zig]].
In addWordsForAFile, you allocate a new string for every single token you find
Because arena allocators generally do not support freeing individual items, every time you encounter a word that already exists in the map, you are wasting that arena.alloc. If a file has 100,000 words but only 5,000 unique words, you are wasting 95,000 allocations!
#+begin_src zig
  while (tokens.next()) |tok| {
    // 1. Use a stack buffer for small words (no allocation!)
    var buf: [128]u8 = undefined;
    var lower_tok: []u8 = undefined;
    var is_stack = false;

    if (tok.len <= buf.len) {
        lower_tok = buf[0..tok.len];
        is_stack = true;
    } else {
        lower_tok = try arena.alloc(u8, tok.len); // Fallback for huge words
    }
    _ = std.ascii.lowerString(lower_tok, tok);

    // 2. Check if it exists WITHOUT allocating
    if (map.getPtr(lower_tok)) |word_ptr| {
        word_ptr.freq += 1;
    } else {
        // 3. It's a new word! Now we allocate from the arena.
        const final_tok = if (is_stack) try arena.dupe(u8, lower_tok) else lower_tok;
        var entry = try map.getOrPut(final_tok);
        entry.value_ptr.key = final_tok;
        entry.value_ptr.freq = 1;
    }
}
#+end_src
